### Contexto

El proyecto trabaja con un ciclo global fijo:

```text
C = 140 s
```

Cada ventana debe cumplir:

```text
verde + amarillo + rojo = C
```

La transición actualmente modifica los offsets de los semáforos para pasar de la ola verde de SUBIDA a la ola verde de BAJADA.

El problema detectado por los scripts de auditoría es que, aunque cada ventana individual conserva:

```text
verde + amarillo + rojo = 140
```

el tiempo entre dos inicios consecutivos de verde puede dejar de ser 140 s.

Esto genera ciclos locales anómalos durante la transición.

La relación importante es:

```text
t[k]   = k*C + offset[k]
t[k+1] = (k+1)*C + offset[k+1]

t[k+1] - t[k] = C + offset[k+1] - offset[k]
```

Por lo tanto, cambiar el offset entre ciclos puede alterar el ciclo observado.

### Objetivo

Necesito que rediseñes/corrijas el algoritmo de transición para que sea matemáticamente coherente con el requisito de **ciclo fijo**.

El objetivo es:

1. Mantener `C = 140 s`.
2. Mantener:

   ```text
   verde + amarillo + rojo = 140
   ```

   en cada ciclo.
3. Mantener amarillo según la configuración.
4. Respetar `min_green_s`.
5. Respetar `min_red_s`.
6. Respetar `max_green_change_fraction_per_cycle`.
7. Llegar finalmente al plan de BAJADA.
8. No generar ciclos locales artificialmente cortos o largos.
9. No solucionar el problema simplemente modificando/eliminando la auditoría.
10. Mantener el histórico capaz de demostrar que la solución es correcta.
